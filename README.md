# T006 — Urban Microclimate Modelling via Neural Surrogates and Computational Fluid Dynamics

## Phase 1: executable machine-learning baseline

This repository contains a reproducible, notebook-first workflow using the **224 idealized UrbanTALES cases**. Each case combines a layout with a wind direction (0° or 45°). The primary validation protocol holds out entire plan families to reduce leakage between related layouts.

The Phase 1 target, `target_U_canopy_mean_m_s`, comes from the raw `U` column in `data/raw/UrbanTALES-flowdata.csv`. The supplied UrbanTALES datasheet describes the flow-data variables as canopy-averaged from ground level to mean building height and defines `U` as wind speed in m/s.

## Run the notebooks in order

Run all cells in the seven notebooks under `Machine Learning Pipeline/`, in numerical order:

1. **ML_01 — Dataset understanding and data dictionary:** reads the raw metadata and flow table, audits all three supplied ZIP archives, validates case/layout/family counts, and builds the processed dataset from raw inputs.
2. **ML_02 — EDA and target definition:** calculates descriptive statistics and displays exploratory plots inline.
3. **ML_03 — Leakage audit and feature engineering:** builds the modeling table, checks the predictor whitelist, and examines feature relationships.
4. **ML_04 — Grouped split and preprocessing:** constructs family-held-out folds and demonstrates leakage-safe preprocessing.
5. **ML_05 — Ridge regression:** trains Ridge regression and computes out-of-fold predictions and metrics.
6. **ML_06 — Random Forest and XGBoost:** trains tree-based models and computes metrics and feature importance.
7. **ML_07 — Evaluation and comparison:** independently computes the model comparisons across validation protocols, uncertainty estimates, and diagnostic plots.

**Run ML_01 first.** Later notebooks intentionally use the processed dataset produced by that notebook. Model notebooks train/evaluate models in executable cells; no precomputed metrics or predictions are supplied as model inputs. Plots are displayed inline. The reproducible processed dataset, generated data dictionary, dataset summary, and raw-archive audit tables from ML_01 are included under `data/processed/`. Rerunning ML_01 regenerates these files from the raw inputs. Model evaluation tables are written to `results/` during execution; precomputed model-result files are not part of this repository.

## Data and scope

- `data/raw/` contains the supplied raw data and three sample ZIP archives.
- `data/processed/` contains the reproducible ML_01 outputs and is not an input to ML_01; the notebook rebuilds and replaces these artifacts from raw data.
- `results/` is generated by the model notebooks and is ignored by Git; no precomputed metrics or predictions are committed.
- The current experiment predicts a **single scalar canopy-averaged wind speed** per idealized case. It is not yet a temperature model, a full spatial-field surrogate, or a replacement for CFD.
- The raw catalogue includes realistic cases, but the current family-based experiment is restricted to the 224 idealized cases.
- The raw catalogue's CL/SM configuration labels differ from the folder-code convention. The original catalogue label is preserved for traceability and excluded from predictors; verify the physical interpretation against the UrbanTALES documentation before making claims about these labels.
- Each supplied ZIP archive contains 32 sample members, not all 224 cases. The profile archive is used for a diagnostic comparison with the full flow-table target; topology and NetCDF archives are inventoried. These samples are not treated as complete spatial-field data.
